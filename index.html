01 / Features

A closer look at your network

Useful router information, right where your smart home lives.

01

Client monitoring

Search, sort and filter known, online and offline clients. Open device details directly from the sensor’s client table.

02

Device tracking

Create connection entities and presence trackers only for selected clients. The client table works without individual trackers.

03

Mesh information

Explore node names, models, uptime, assigned online clients and available port link speeds reported by SRM.

04

CPU & RAM statistics

View CPU, RAM and swap usage with larger gauges and custom graphs. System data refreshes every 5 minutes.

05

Network status

View available network status information from your Synology SRM router.

06

Wake-on-LAN

Send a wake-up request to compatible devices on your network.

02 / Installation

Up and running

Choose HACS for convenient installation and updates, or install manually from the release ZIP. Both methods use the same Home Assistant setup interface.

Recommended method

HACS

Add the project as a custom repository. HACS must already be installed in your Home Assistant instance.

  1. 1

    Add the repository

    Use the button below and confirm adding the repository in HACS. Alternatively, open Custom repositories in HACS, paste the project URL and select Integration.

  2. 2

    Install the integration

    Open Synology SRM Extended in HACS and download it. HACS also makes subsequent updates easier.

  3. 3

    Restart Home Assistant

    Restart Home Assistant after installation. Then continue with the SRM connection instructions below both guides.

https://github.com/Vachler/synology-srm-extended

Alternative method

Manual installation

Download the release package and copy the integration into your Home Assistant configuration.

  1. 1

    Download the integration

    Get the ZIP from the latest GitHub release. Extract it on your computer.

  2. 2

    Copy the integration folder

    Copy the synology_srm_extended folder containing manifest.json into your Home Assistant custom_components directory. Create custom_components if it does not exist.

  3. 3

    Restart Home Assistant

    Restart Home Assistant to load the custom integration.

4

Connecting to SRM

In Home Assistant, open Settings → Devices & services → Add integration. Search for Synology SRM Extended and complete the setup form.

Enter the router IP address or hostname without a protocol or port. Enter the port separately: commonly 8001 for HTTPS or 8000 for HTTP. Use the actual port configured on your router and your SRM account credentials. HTTPS and certificate verification are enabled by default.

03 / Compatibility

Built for Synology SRM

Tested on Synology RT6600ax with SRM 1.3.2-9366 Update 2. Development and testing focus on Home Assistant Core 2026.9.3.

Verified setup

RT6600ax · SRM 1.3.2

RT2600ac and MR2200ac have not been separately verified as the primary router. API availability depends on firmware and account permissions.

Requirements

Home Assistant Core 2026.9.3

The HA server must reach the router address and port. One router configuration entry is supported. Interactive two-factor authentication is not implemented. Custom views and WOL require HA administrator access.

04 / Privacy & security

Privacy & security

Communication uses local polling. No cloud account or QuickConnect is required. Credentials are stored through standard Home Assistant configuration entries.

  • HTTPS and certificate verification are enabled by default. Use a trusted certificate where possible.
  • The integration does not change router settings. Wake-on-LAN is a separate action triggered manually in HA.
  • Diagnostics omit passwords, sessions, client names, MAC and IP addresses, and SSIDs. Check screenshots separately before sharing.

This website uses no analytics, cookies, external fonts or third-party scripts. Repository and download links open GitHub; the HACS shortcut opens My Home Assistant. Those services apply their own policies.

05 / Known limitations

Known limitations

Available data depends on the router model, firmware and account permissions. This is an unofficial community integration.

  • Clients refresh every 30 seconds by default; system, WAN and mesh data refresh every 5 minutes. Changes are not immediate SRM events.
  • Tracking is optional and selected manually. A phone being offline does not prove a person is absent; randomized MAC addresses may create new identities.
  • Router restart, traceroute, Wi-Fi changes, client blocking, Safe Access and Threat Prevention are not implemented.
  • WAN status is reported by SRM, not an independent Internet test. Mesh port speeds do not identify node backhaul links.
  • Client traffic requires an input unit and RX direction setting; wired traffic may be missing. Custom graphs use temporary history, not long-term measurements.
  • WOL delivery across VLANs is not guaranteed. Sending a packet does not confirm the device woke up.
